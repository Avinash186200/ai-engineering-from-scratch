# AI Engineering from Scratch with Avinash

Code for the YouTube series **AI Engineering from Scratch with Avinash**: ten days that go from
"what is a token" to a tested, containerised AI assistant, plus interview practice.

Every example uses one running project: a **research assistant chatbot for Indian mutual fund
analysts**. All fund data here is **synthetic** (generated by `data/make_data.py` with a fixed
seed). Nothing in this repo is investment advice, and no real fund is described.

No API key is needed. Every LLM script runs with a deterministic `FakeLLM` by default.
Add `--real` (and set `ANTHROPIC_API_KEY`) to use Claude through the same adapter.

A good way to use this repo: watch an episode, open its lesson page, then run the commands in the table below and
change things until you can predict what the code will print.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python data/make_data.py           # writes data/funds.csv (also built automatically on first use)
```

Python 3.11. Run every command from the repo root.

## The tools (core/fund_model.py)

- `rank_funds(as_of="", top_n=5, model="quantile", category=None)` returns
  `{"as_of", "model", "n_scored", "top": [{"rank", "fund", "predicted_return", "nav"}], "excluded", "caveat"}`.
  `predicted_return` is a decimal (0.0099 = +0.99%) over the next 20 trading days.
  A weekend, a bad date, or a date outside the data returns `{"error": "..."}`, for example
  `{"error": "No data for 2025-06-21 (not a business day?). Try a nearby weekday."}`.
  An unknown `model` raises `ValueError`; the agent turns it into an error result.
- `lookup_definition(term)` (alias `lookup_term`), `model_info()`, `fund_info(name)`,
  and `compare_models(as_of)`, the solved Day 3 exercise.

## Notes per day

- **Day 1**: `tokens_demo.py` uses `tiktoken` (`cl100k_base`); without it, or offline, it
  runs a toy BPE instead. `sft_examples.jsonl` holds the two SFT records from the video.
- **Day 2**: `system_prompt.md` is the chatbot's system prompt; the Day 3 agent loads it.
- **Day 3**: three questions on thread `priya-1` (12 messages), an empty `rahul-1`, failures
  as data, streaming updates, and a breakpoint before tools.
  Try `python day03_agents/agent.py --ask "Which funds look best on 2025-06-20?"`.
- **Day 4**: the server speaks MCP over stdio; the client starts it as a child process.
  To use it from an MCP host, point the host at `python day04_mcp/fund_mcp_server.py`.
  Works with `mcp` 1.x (`FastMCP`) and 2.x (renamed `MCPServer`).
- **Day 5**: the corpus is `day05_rag/docs/` (`fund_glossary.md` plus three factsheets).
  Uses `sentence-transformers` if installed, else a hashed bag-of-words embedder (no downloads).
  `--mode dense|keyword|hybrid`, `--size` and `--overlap` change the search and the chunks.
- **Day 6**: exits with code 1 if the pass rate is below 90%, so CI blocks the change.
- **Day 7**: about 20 seconds. The metrics are illustrative: the data is synthetic.
- **Day 8**: `uvicorn day08_production.app:app --port 8000`, then open `/docs`.
  `LLM_PROVIDERS=claude,fake` sets the failover order. If every provider is down, `/chat`
  still returns the raw ranking from `rank_funds`.
  Docker: `docker build -f day08_production/Dockerfile -t chatbot .` from the repo root.

## Using real Claude

```bash
python day03_agents/agent.py --real
```

The model name is set once in `core/llm.py`.

## Notes on the videos

- Numbers shown in the videos (predicted returns, costs, metrics) are illustrative. Your run of the code will print
  different values, because the fund data is synthetic and generated on your machine.
- A few slides show simplified sketches rather than the exact file: the Day 9 tool-server sketch, the Day 8
  Dockerfile (the real one copies a few more folders), and the MCP-enabled agent in Day 4 Part 4 (left as an exercise).
- The data panel runs from 2020-01-01 to 2025-06-30; weekends and dates outside that range return an error by design.
